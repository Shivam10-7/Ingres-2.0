# 📘 **Project Title: JalSathi – Intelligent Groundwater Data Chatbot**

---

# 🎯 **1. Project Overview**

The main objective of the project is to create a chatbot system that can understand natural language queries related to groundwater data and provide accurate, structured responses.

The system allows users to ask questions such as:

* “Groundwater level in Pune”
* “Compare extraction and recharge in Nagpur and Pune”

and converts them into meaningful outputs using data processing and AI techniques.

---

# 🚀 **2. Motivation**

* Current groundwater portals are **complex and not user-friendly**
* Users require **technical knowledge** to query data
* No support for **natural language queries**
* Lack of **real-time intelligent insights**

👉 JalSathi solves this by enabling **simple, conversational access to groundwater data**

---

# 🧠 **3. System Architecture**

```text
User Query
   ↓
Intent & Entity Extraction (Resolver)
   ↓
Query Understanding (Intent Classification + Location Detection)
   ↓
Query Planning (Mapping to SQL)
   ↓
Database Execution
   ↓
Response Generation (JSON / Visualization)
```

---

# 🔍 **5. Methodology**

## 🔹 Step 1: Data Preparation

* Hierarchical JSON created:

  * State → District → Assessment Unit
* Intent database (`intent_db.json`) created with domain-specific phrases

---

## 🔹 Step 2: Intent Detection

* Query converted into embeddings using MiniLM
* Compared with predefined intent phrases using cosine similarity
* Top intent selected using ranking + threshold filtering

---

## 🔹 Step 3: Location Extraction

* Tokenization + phrase generation (uni, bi, tri-grams)
* Exact match using sets
* Fuzzy matching using RapidFuzz
* Stopword filtering to remove noise
* Hierarchy mapping (Unit → District → State)

---

## 🔹 Step 4: Output Generation

* Structured JSON returned:

```json
{
  "intents": ["water_level"],
  "locations": [
    {
      "type": "district",
      "value": "PUNE",
      "state": "MAHARASHTRA"
    }
  ]
}
```

---

## 🔹 Step 5: API Integration

* FastAPI used to expose endpoints
* `/extract` endpoint processes user queries
* Swagger UI for testing

# ⚠️ **7. Challenges Faced**

### 🔹 1. SQL Query Generation

Understanding user intent and converting it into accurate SQL queries was challenging.

### 🔹 2. LLM Limitations

LLMs are probabilistic and may produce inconsistent results, so deterministic logic was added.

### 🔹 3. Location Resolution

Handling multiple locations and fuzzy matching without noise required optimization.
